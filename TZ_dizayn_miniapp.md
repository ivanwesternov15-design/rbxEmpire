# ТЗ: Дизайн Telegram Mini App "rbxflare"

> Версия: 1.0 — этап "Главное" + навигация
> Стек: HTML + CSS + JS (frontend), Python 3.11 (только для получения/валидации данных Telegram)
> Стиль: UI/UX 2026, glassmorphism, плавные микро-анимации
> ⚠️ Это ТЗ описывает **только дизайн и структуру**. Игровая/бизнес-логика (начисление Robux/Coins, карточки, рефералы, вывод средств) сюда не входит и реализуется отдельным этапом.

---

## 1. Общее описание

Telegram Mini App — личный кабинет пользователя с балансами (Robux, Coins), ежедневными карточками, стейкингом, заданиями, рефералами и профилем. Приложение открывается внутри Telegram, получает данные пользователя через `Telegram.WebApp.initDataUnsafe` (ник, аватар, id) и кэширует их локально.

---

## 2. Цветовая палитра

Основной вертикальный/диагональный градиент фона (использовать во всех крупных контейнерах и как фон `body`):

```css
--color-1: #11212D; /* самый тёмный, база */
--color-2: #253745;
--color-3: #4A5C6A;
--color-4: #9BA8AB;
--color-5: #CCD0CF; /* самый светлый, акценты/текст на тёмном */
```

Пример базового градиента:

```css
background: linear-gradient(160deg, #11212D 0%, #253745 30%, #4A5C6A 60%, #9BA8AB 85%, #CCD0CF 100%);
```

**Правило прозрачности:** все окна, карточки, панели и модалки — полупрозрачные (glassmorphism) на основе палитры:

```css
.glass-panel {
  background: rgba(37, 55, 69, 0.55);   /* на основе --color-2 */
  backdrop-filter: blur(18px) saturate(140%);
  -webkit-backdrop-filter: blur(18px) saturate(140%);
  border: 1px solid rgba(155, 168, 171, 0.18); /* тонкая обводка --color-4 */
  border-radius: 20px;
  box-shadow: 0 8px 32px rgba(17, 33, 45, 0.35);
}
```

Более светлые/акцентные плашки (Robux/Coins/Streak, карточки) — брать `rgba(74, 92, 106, 0.4)` или `rgba(155, 168, 171, 0.15)` в зависимости от контраста с содержимым.

Текст:
- Основной текст — `#CCD0CF` / `#FFFFFF` с пониженной непрозрачностью для второстепенного (напр. `rgba(204,208,207,0.7)`).
- Акцентные цифры (баланс, streak) — можно чуть светлее/с лёгким glow-эффектом через `text-shadow`.

## 3. Общая структура layout

```
┌─────────────────────────────┐
│         Верхняя панель        │  ← аватар / ник / ID (фиксирована, всегда видна. Кроме "Профль")
├─────────────────────────────┤
│                               │
│        Контентная зона        │  ← меняется в зависимости от раздела
│      (скролл, safe-area)      │
│                               │
├─────────────────────────────┤
│    Нижняя навигационная       │  ← фиксирована, всегда видна
│           панель              │
└─────────────────────────────┘
```

Разделы (5 штук), переключаются через нижнюю навигацию без перезагрузки страницы (SPA-подход, показ/скрытие секций или роутинг на history API):

1. Главное
2. Карточки
3. Рефералы
4. Задания
5. Профиль

На этом этапе детально прорабатываем **только "Главное"** + саму навигацию. Остальные разделы — заглушки-контейнеры с тем же стилем панелей, наполнение — следующими этапами.

---

## 4. Нижняя навигационная панель

### 4.1 Общий вид
- Горизонтальная панель, фиксирована снизу экрана (`position: fixed; bottom: 0`), с отступом от края под safe-area iOS.
- Полупрозрачный фон по палитре (см. `.glass-panel`), скругление верхних углов (например `border-radius: 24px 24px 0 0`).
- 5 пунктов равномерно распределены (`display: flex; justify-content: space-around`).
- Каждый пункт: SVG-иконка сверху, под ней подпись текстом (12–13px, `#CCD0CF`).

### 4.2 Активный пункт
- Активная иконка/подпись — светлее и/или с акцентной подсветкой (например, `filter: drop-shadow(0 0 6px rgba(204,208,207,0.6))`).
- Под активной иконкой — плавающий индикатор (маленькая полоска или "пилюля"-подложка), которая **анимированно перемещается** между пунктами при переключении (transition по `transform: translateX()`, 250–350ms, `cubic-bezier(0.4, 0, 0.2, 1)`).
- Лёгкий scale-эффект иконки при активации (`transform: scale(1.1)`), возврат к обычному размеру у остальных.

### 4.3 Окно выбора категории (доп. фича)
При тапе/long-press по любому пункту (или отдельной кнопке "меню") — красиво появляется **окно выбора категории**:
- Полупрозрачная модалка/шторка снизу вверх (bottom sheet), с тем же стеклянным стилем.
- Внутри — список всех 5 разделов крупными карточками с иконкой + названием + коротким описанием.
- Анимация появления: slide-up + fade-in (300–400ms), затемнение фона (`backdrop`) с fade.
- Закрытие: свайп вниз, тап по фону, кнопка закрытия.

### 4.4 Анимация переключения между разделами
- При смене раздела — контентная зона анимируется (fade + небольшой slide по горизонтали, 200–300ms), чтобы переход не был резким.
- Направление slide можно связывать с порядком пунктов (влево/вправо), либо использовать простой crossfade — на усмотрение реализации, главное плавность.

## 5. Раздел "Главное"

### 5.1 Верхняя панель профиля
Расположена в самом верху раздела "Главное" (не показывается в других разделах — там просто нет этого блока или используется компактная версия, если нужно для консистентности — уточним на следующем этапе).

Содержимое:
- Аватар пользователя (круглый, обводка в стиле палитры, лёгкая тень/glow).
- Под/рядом с аватаром: **NickName** (жирный, крупный шрифт).
- Под NickName: **ID: {telegram_id}** (мельче, приглушённый цвет).

Источник данных: Telegram WebApp API.

```js
const tgUser = Telegram.WebApp.initDataUnsafe?.user;
// tgUser.id, tgUser.first_name, tgUser.username, tgUser.photo_url
```

**Кэширование:** сохранять полученные данные пользователя локально, чтобы не мигал пустой профиль при повторном открытии:

- Вариант 1 (простой): `localStorage` — ключ вида `rbxflare_user`, JSON со сроком жизни (timestamp) для инвалидации.
- Вариант 2 (более гибкий): `IndexedDB` — если позже понадобится кэшировать больше данных (баланс, карточки, статистику), лучше сразу закладывать IndexedDB через небольшую обёртку (напр. `idb`), т.к. localStorage ограничен по объёму и синхронный.
- Рекомендация: на дизайн-этапе — заглушка на localStorage, с явным TODO/комментарием, что структура кэша будет расширяться при подключении бэкенда.

Пока данные не подгрузились — показывать skeleton-заглушку (пульсирующий полупрозрачный блок) вместо аватара/ника.

### 5.2 Панель статистики (Robux / Coins / Streak)
Три окна в ряд (на маленьких экранах — можно вертикальный wrap):

| Окно | Содержимое |
|---|---|
| Robux | SVG-иконка + число + подпись "Robux" |
| Coins | SVG-иконка + число + подпись "Coins" |
| Streak | SVG-иконка (например, огонёк) + число дней + подпись "Streak" |

Требования к стилю:
- Каждое окно — отдельная стеклянная карточка (см. `.glass-panel`, чуть более компактный радиус, например `16px`).
- Иконка — с лёгкой анимацией idle (например, для Streak — покачивание/пульсация "огонька" каждые несколько секунд; для Robux/Coins — лёгкий shimmer/блик, пробегающий по иконке).
- Число баланса — анимированный счётчик при изменении значения (count-up эффект), крупный акцентный шрифт.
- При обновлении значения — короткая вспышка/подсветка карточки (пульс рамки), чтобы пользователь заметил изменение.

### 5.3 Панель "Ежедневные карточки"
Блок с заголовком: SVG-иконка + текст **"Ежедневные карточки"**.

Содержимое (дизайн-макет, без логики):
- Ряд/сетка из **3 карточек**, каждая — стеклянная плашка с иконкой/иллюстрацией, названием и, например, потенциальной наградой.
- Одна из карточек может быть выбрана пользователем (визуально: обводка/подсветка при выборе, остальные — приглушаются/блокируются до следующего дня — только на уровне UI-состояния).
- Ниже карточек — короткий пояснительный текст о механике: как получить карточку сегодня, когда обновляется набор карточек, что нужно сделать, чтобы её забрать (например: "Каждый день доступны 3 новые карточки. Выберите одну — она станет вашей наградой дня. Новые карточки появляются каждые 24 часа."). Текст стилизуется приглушённым цветом, возможно с маленькой иконкой "инфо".

### 5.4 Панель быстрых действий (4 окна)
Заголовок или просто сетка 2×2 (или 1×4 на широких экранах) из кликабельных окон:

| Окно | Иконка | Действие при клике |
|---|---|---|
| Задания | SVG | Переключает нижнюю навигацию на раздел **"Задания"** |
| Стейкинг | SVG | Переключает на соответствующий раздел (уточнить: если отдельного пункта навигации нет — временно можно вести в "Карточки" или зарезервировать для будущего раздела) |
| Рефералы | SVG | Переключает на раздел **"Рефералы"** |
| Вывод | SVG | Переключает на раздел **"Профиль"** (там будет блок вывода) |

Стиль плашек — тот же `.glass-panel`, с hover/tap-эффектом (лёгкое увеличение/подсветка при нажатии, ripple-эффект приветствуется).

> Примечание: в оригинальном списке разделов навигации нет пункта "Стейкинг" — уточни на следующем шаге, куда он должен вести (в "Карточки"? отдельный будущий раздел?), чтобы не оставлять битую ссылку.

## 6. Остальные разделы (заглушки на этом этапе)

Разделы **Карточки**, **Рефералы**, **Задания**, **Профиль** — на данном этапе оформляются как пустые контейнеры с тем же фоном/паттерном (можно добавить крупный SVG-плейсхолдер по центру + подпись "Раздел в разработке"), чтобы навигация между всеми 5 пунктами уже полноценно работала и была протестирована визуально. Детальный дизайн каждого раздела — следующими этапами (как ты и написал — "будем делать поэтапно").

## 7. Требования 2026 UI/UX уровня

- **Glassmorphism** везде, где указано (см. раздел 2).
- **Микро-анимации**: hover/tap-эффекты на всех интерактивных элементах, плавные transition (200–400ms, ease-out/cubic-bezier), никаких резких появлений без fade/slide.
- **Fluid typography**: размеры шрифта через `clamp()`, чтобы адаптироваться под разные экраны Telegram (от компактных Android до iPad-подобных).
- **Safe area**: обязательно учитывать `env(safe-area-inset-*)` для нижней навигации и верхней панели (актуально для iOS в Telegram).
- **Тёмная тема по умолчанию** (палитра и так тёмная), с адаптацией под `Telegram.WebApp.colorScheme`, если потребуется.
- **Skeleton-состояния** при загрузке данных (профиль, балансы) — не показывать "пустоту" или резкие скачки контента.
- **Тактильная отдача**: использовать `Telegram.WebApp.HapticFeedback` на ключевых действиях (переключение вкладок, выбор карточки, тап по быстрым действиям).
- **Адаптивность**: mobile-first, но не ломаться на десктопной версии Telegram Web.

```
    app.py           ← минимальный сервис, только валидация Telegram initData / приём данных пользователя

  .gitignore
```

## 9. Безопасность (важно перед публикацией в GitHub)

- Токен бота **не хранить в коде**. Только через переменные окружения / `.env`, добавленный в `.gitignore`.
- Токен, который был показан в переписке, считать скомпрометированным — **перевыпустить через @BotFather → /revoke**.
- То же самое касается любых будущих API-ключей (GitHub PAT и т.п.) — передавать инструментам через переменные окружения, никогда не коммитить в открытый репозиторий.

- Внутри — список всех 5 разделов крупными карточками с иконкой + названием + коротким описанием.
- Анимация появления: slide-up + fade-in (300–400ms), затемнение фона (`backdrop`) с fade.
- Закрытие: свайп вниз, тап по фону, кнопка закрытия.

### 4.4 Анимация переключения между разделами
- При смене раздела — контентная зона анимируется (fade + небольшой slide по горизонтали, 200–300ms), чтобы переход не был резким.
- Направление slide можно связывать с порядком пунктов (влево/вправо), либо использовать простой crossfade — на усмотрение реализации, главное плавность.

## 5. Раздел "Главное"

### 5.1 Верхняя панель профиля
Расположена в самом верху раздела "Главное" (не показывается в других разделах — там просто нет этого блока или используется компактная версия, если нужно для консистентности — уточним на следующем этапе).

Содержимое:

- Под/рядом с аватаром: **NickName** (жирный, крупный шрифт).
- Под NickName: **ID: {telegram_id}** (мельче, приглушённый цвет).

Источник данных: Telegram WebApp API.

```js
const tgUser = Telegram.WebApp.initDataUnsafe?.user;
// tgUser.id, tgUser.first_name, tgUser.username, tgUser.photo_url
```

**Кэширование:** сохранять полученные данные пользователя локально, чтобы не мигал пустой профиль при повторном открытии:

- Вариант 2 (более гибкий): `IndexedDB` — если позже понадобится кэшировать больше данных (баланс, карточки, статистику), лучше сразу закладывать IndexedDB через небольшую обёртку (напр. `idb`), т.к. localStorage ограничен по объёму и синхронный.
- Рекомендация: на дизайн-этапе — заглушка на localStorage, с явным TODO/комментарием, что структура кэша будет расширяться при подключении бэкенда.

## 7. Требования 2026 UI/UX уровня

- **Glassmorphism** везде, где указано (см. раздел 2).
- **Микро-анимации**: hover/tap-эффекты на всех интерактивных элементах, плавные transition (200–400ms, ease-out/cubic-bezier), никаких резких появлений без fade/slide.
- **Fluid typography**: размеры шрифта через `clamp()`, чтобы адаптироваться под разные экраны Telegram (от компактных Android до iPad-подобных).
- **Safe area**: обязательно учитывать `env(safe-area-inset-*)` для нижней навигации и верхней панели (актуально для iOS в Telegram).
- **Тёмная тема по умолчанию** (палитра и так тёмная), с адаптацией под `Telegram.WebApp.colorScheme`, если потребуется.
- **Skeleton-состояния** при загрузке данных (профиль, балансы) — не показывать "пустоту" или резкие скачки контента.
- **Тактильная отдача**: использовать `Telegram.WebApp.HapticFeedback` на ключевых действиях (переключение вкладок, выбор карточки, тап по быстрым действиям).
- **Адаптивность**: mobile-first, но не ломаться на десктопной версии Telegram Web.

## 11. Раздел "Карточки" (Инвентарь)

### 11.1 Верхняя панель
Та же панель профиля, что и в "Главном" (аватар / ник / ID) — компактная версия, для визуальной консистентности между разделами.

### 11.2 Панель "Инвентарь"
Заголовок панели: SVG-иконка + текст **"Инвентарь"**.

Справа в этой же панели — два индикатора:

| Индикатор | Значение | Цвет |
|---|---|---|
| Стейкинг | `0` — нет завершённых стейкингов | серый (`rgba(155,168,171,0.5)`) |
| | `N` — есть хотя бы 1 завершённая карточка | зелёный акцент (например `#4ADE80`, с лёгким glow) |
| Инвентарь | `0` — карточек нет | серый |
| | `N` — есть хотя бы 1 карточка | зелёный акцент |

Формат отображения: `Стейкинг: 0` и `Карточки: 0` (или через "/", как в макете — уточни финальный текстовый формат на этапе вёрстки).

- **Hover/tap-эффект**: при наведении (десктоп) или долгом тапе (мобилка) на индикатор — появляется всплывающая подсказка (tooltip/popover) с расширенной информацией, например: "У вас 3 карточки готовы к стейкингу" или "1 карточка завершила стейкинг — заберите награду". Анимация появления — fade + небольшой scale (150–200ms).
- В правом верхнем углу этой же панели — кнопка **"Магазин"** (иконка сумки/корзины + текст или просто иконка на маленьких экранах), открывает модалку магазина (см. 11.5).

### 11.3 Сетка карточек

**Критично по адаптивности:** ровно **2 карточки в ряд** на мобильных экранах/Mini App (`grid-template-columns: repeat(2, 1fr)`), никогда не больше. Остальные карточки уходят вертикально вниз (обычный grid-flow, скролл).

Карточки, которые нужно поддержать: `Basic`, `Silver`, `Gold`, `Diamond`, `Mythic` (файлы лежат в `/assets/cards/Basic.png`, `Silver.png`, `Gold.png`, `Diamond.png`, `Mythic.png`).

#### Цветовые акценты редкости (взяты из референсных изображений)
Каждая карточка в инвентаре — это картинка (PNG) на подложке-плашке с **анимированным градиентом**, цвета которого соответствуют редкости (взяты из самих референсов):

```css
--rarity-basic:   linear-gradient(135deg, #1a1d21 0%, #2c3036 50%, #3a3f45 100%);
--rarity-silver:  linear-gradient(135deg, #8e9aa3 0%, #d4dade 50%, #ffffff 100%);
--rarity-gold:    linear-gradient(135deg, #7a4a00 0%, #ffb800 45%, #ff8c1a 75%, #ffd76a 100%);
--rarity-diamond: linear-gradient(135deg, #041b3d 0%, #0066ff 40%, #00d4ff 70%, #8be9ff 100%);
--rarity-mythic:  linear-gradient(135deg, #2a0845 0%, #8b3ce0 30%, #ec4899 60%, #f59e0b 85%, #a855f7 100%);
```

- Подложка под PNG карточки — animated gradient (`background-size: 200% 200%`, `animation: gradientShift 6–8s ease infinite`, плавное перетекание оттенков), плюс мягкое свечение по краю карточки цвета редкости (`box-shadow: 0 0 24px var(--rarity-color)`).
- Basic — статичная, без анимации свечения (самая базовая редкость, минимум эффектов).
- Silver — лёгкое свечение, без сильных бликов.
- Gold — свечение + лёгкий shimmer-блик, пробегающий по карточке раз в несколько секунд.
- Diamond — более выраженное пульсирующее свечение + блики-искры.
- Mythic — максимальный эффект: анимированный радужный градиент, вращающееся кольцо/аура (как на референсе), самая "дорогая" визуально карточка.

#### Содержимое карточки (под изображением)
```
[PNG карточки]
Цена: 120 R   ← "R" = SVG-иконка валюты Robux рядом с числом
Получена: 18.08.26
Silver        ← название редкости, цветом редкости
Статус: Готова к стейкингу / Стейкинг завершён
[ Кнопка: Стейкинг ]  или  [ Кнопка: Прогресс ]
```

- Кнопка **"Стейкинг"** показывается, если карточка ещё не в стейкинге.
- Кнопка **"Прогресс"** показывается, если карточка уже застейкана (открывает окно прогресса, см. 11.4.2).
- Кнопки — стеклянные, с hover/tap-анимацией (scale + подсветка цветом редкости карточки).

### 11.4 Модальные окна стейкинга

#### 11.4.1 Окно выбора времени стейкинга
Появляется по кнопке "Стейкинг" — bottom sheet / модалка со списком вариантов:

| Срок | Бонус % | Доп. Robux |
|---|---|---|
| 12 часов | +0.5% | +0 Robux |
| 24 часа | +1% | +0 Robux |
| 3 дня | +3% | +1 Robux |
| 7 дней | +7% | +3 Robux |

- Каждый вариант — отдельная стеклянная плашка-строка, кликабельная, с hover/tap подсветкой.
- Значения `%` и бонусов должны быть **настраиваемыми через админ-панель** в профиле (см. раздел 14) — на дизайн-этапе просто выводим значения из конфига/заглушки, не хардкодим намертво в разметке.
- После выбора — подтверждение (короткая анимация "успех" + закрытие модалки), карточка визуально переходит в статус "в стейкинге".

#### 11.4.2 Окно прогресса стейкинга
Заголовок: **"СТЕЙКИНГ — ПРОГРЕСС"**.

Содержимое:
- Название карточки и её редкость (цвет редкости).
- Строка: `Стейкинг: 12 часов` (выбранный срок).
- Таймер обратного отсчёта: `Осталось: Ч ч М мин С сек` — обновляется в реальном времени (когда не завершён).
- Когда время вышло — вместо таймера: **"Стейкинг завершён"**.
- Круговой/линейный прогресс-бар (SVG, анимированный) от 0% до 100%, синхронизирован с таймером.
- Блок награды: **"Награда: 300–303 Robux"** (диапазон, т.к. итоговое число определяется бизнес-логикой — здесь только дизайн вывода).
- Кнопка **"Забрать и стереть карточку"** — активна только после 100%; по нажатию — анимация "сбора" (например частицы/свечение исчезает, карточка визуально "тает"/scale-out) и удаление карточки из инвентаря.

SVG-анимации для этого окна: анимированное кольцо прогресса, пульсирующий индикатор при завершении, конфетти/искры при получении награды (лёгкие, не аляповатые — в духе минимал-дизайна 2026).

### 11.5 Магазин карточек
Модалка/отдельный экран, открывается кнопкой "Магазин" из шапки инвентаря.

- Список карточек, доступных к покупке **за Coins** (не Robux).
- Каждая позиция: изображение карточки + редкость + цена в Coins + доступное количество (лимит) + кнопка "Купить".
- Если лимит исчерпан — карточка отображается приглушённой, кнопка неактивна, текст "Раскуплено".

**Админ-панель (в Профиле):** возможность добавлять/удалять карточки, которые сейчас продаются в магазине, и указывать их количество (лимит). Дизайн — простая форма: выбор редкости карточки, поле "Количество", поле "Цена в Coins", кнопка "Опубликовать в магазин".

## 12. Раздел "Рефералы"

### 12.1 Общий вид
Тот же стеклянный стиль. Структура сверху вниз:

1. Заголовок **"Пригласить друзей"** + счётчик приглашённых (например `1`).
2. Блок **"Твоя реферальная ссылка"**:
   - Поле со ссылкой вида `https://t.me/rbxflare_bot?start=ref_{user_id}` (нередактируемое, с моноширинным/приглушённым шрифтом).
   - Кнопка **"Поделиться"**.
   - Кнопка **"Копировать"**.
3. Текстовый блок с условиями:
   - "За 1 задание друга ты получишь Gold Card + 500 coins"
   - "За активность друга (3 из 3 выполненных заданий) ты получишь Diamond Card"
   - Стилизовать как отдельную инфо-плашку с акцентной иконкой (например ⓘ или подарок), не сплошным текстом.
4. Блок **"Мои друзья"** — список приглашённых:
   - Аватар + имя друга.
   - Прогресс заданий: `0 / 7 заданий` (текст или мини прогресс-бар).
   - Срок/давность: `6 дней` (когда присоединился).
   - Пустое состояние (если друзей ещё нет) — иллюстрация-заглушка + текст "Пригласи первого друга и получи награду".

### 12.2 Кнопка "Поделиться" — техническая деталь дизайна
Требование: **приложение не должно закрываться**, только сворачиваться/уходить в фон, пока пользователь выбирает, кому переслать сообщение — как обычная пересылка в Telegram.

Правильный способ реализации (Telegram WebApp API):
```js
Telegram.WebApp.shareURL(
  "https://t.me/rbxflare_bot?start=ref_8414792453",
  "Залетай в rbxflare — забирай карточки и Robux 🚀"
);
```
Это откроет нативное окно Telegram "Переслать/Поделиться" поверх мини-аппа, само приложение при этом **не закрывается** — именно тот эффект, который нужен ("как будто пересылаю сообщение другу"). Если `shareURL` недоступен в конкретной версии клиента — fallback на `Telegram.WebApp.openTelegramLink('https://t.me/share/url?url=' + encodeURIComponent(link) + '&text=' + encodeURIComponent(text))`.

На кнопке — короткая tap-анимация (scale + иконка "поделиться" с лёгким bounce).

### 12.3 Кнопка "Копировать"
Копирует в буфер обмена готовый текст + ссылку одной строкой (например: "Залетай в rbxflare — забирай карточки и Robux 🚀 https://t.me/rbxflare_bot?start=ref_8414792453"). После нажатия — краткий визуальный отклик: иконка меняется на "галочку" на 1.5–2 секунды + всплывающий тост "Скопировано".

## 13. Раздел "Задания"

### 13.1 Структура списка
Список карточек-заданий, каждая — отдельная стеклянная панель:

```
[SVG-иконка задания]  Название задания
                        Описание (что нужно сделать)
                        Статус: Выполнено / В процессе
                        Прогресс: 5 / 5   (если применимо)
                        Награда: +60 (получено / ожидает)
```

Примеры заданий из ТЗ: "Собери первую карточку", "Собери 5 карточек", "Заходи 3 дня подряд", "Отправь карточку в стейкинг", "Пригласи друга", "Смени фон карточки", "Накопи 500 Robux".

### 13.2 Состояния и стили
- **Выполнено**: иконка-галочка (зелёный акцент), плашка слегка "приглушена" по яркости фона, текст "+N получено" зелёным.
- **В процессе**: прогресс-бар (линейный, анимированный заполнением), текст "+N" (без "получено") приглушённым цветом, сама плашка чуть ярче/акцентнее, чтобы визуально мотивировать завершить.
- Иконка задания — своя SVG под тип задания (сбор карточек, серия входов, стейкинг, рефералы, кастомизация, баланс и т.д.).

### 13.3 Анимации и интерактив
- **Tap/hover на плашку**: лёгкий подъём (небольшой `translateY` + усиление тени), курсор pointer.
- **При наведении** — можно показывать доп. tooltip с более подробным описанием условия выполнения (если текста не хватает в самой плашке).
- **При выполнении задания** (переход из "В процессе" в "Выполнено") — анимация: прогресс-бар доливается до 100%, вспышка/пульс рамки зелёным, иконка меняется на галочку с небольшим bounce-эффектом, всплывает "+N" с лёгким движением вверх и затуханием (как игровой поп-ап награды).
- Список можно группировать (например "Активные" сверху, "Выполненные" снизу) или сортировать по статусу — на усмотрение вёрстки, главное чтобы выполненные не терялись среди активных.

## 14. Раздел "Профиль"

### 14.1 Базовый блок (этот этап)
Верх раздела — карточка профиля:

- Аватар (из Telegram, круглый, обводка в палитре).
- Пометка роли, если применимо (например бейдж **"ВЛАДЕЛЕЦ"** — стилизованный лейбл с акцентной подсветкой, показывается только для соответствующей роли/id).
- **Username** (например `Senku`) — крупно.
- **@handle** (например `@qzysl`) — приглушённым цветом рядом/под именем.
- **ID:** `8414792453` — мелким приглушённым текстом.
- **О себе / bio** — подтягивается из Telegram-профиля (`Telegram.WebApp.initDataUnsafe.user` не содержит bio напрямую — если Bot API не отдаёт bio в этом объекте, потребуется отдельный запрос через Bot API `getChat` на бэкенде; на дизайн-этапе просто верстаем блок с текстом bio и, если есть, дополнительной строкой вида `ⓘ host: @username`, как в примере).
- **Первый вход**: дата первого захода в мини-апп, например "18 августа 2026 г." (берётся из кэша/бэкенда при первой инициализации пользователя).

### 14.2 Нижние вкладки/пункты
Горизонтальный ряд или список из 4 пунктов:
- **Настройки**
- **История**
- **Поддержка**
- **О приложении**

Каждый — кликабельная стеклянная плашка/таб с иконкой, ведёт в соответствующий под-экран (детальное наполнение каждого под-экрана — отдельным этапом, сейчас закладываем только сами точки входа и переходы с анимацией).

### 14.3 Админ-панель (для роли "Владелец")
Доступна только пользователю с соответствующим id/ролью, отдельным пунктом в "Профиле" (например скрытая вкладка "Админ", видимая только владельцу). Содержит на этом этапе:
- Настройку % и бонусов стейкинга по срокам (12ч/24ч/3д/7д) из раздела 11.4.1.
- Управление ассортиментом магазина карточек из раздела 11.5 (какие карточки продаются и в каком количестве).

Оформление — та же стеклянная эстетика, но можно добавить более "техничный" акцент (например моноширинные поля ввода), чтобы визуально отличать админ-инструменты от обычного пользовательского интерфейса.
